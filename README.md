# 全集公开｜The Web3 社区 DeFi 企业级项目实战：FishCake EventFi 项目开发


学完 Solidity、ERC20、ERC721 和常见 DeFi 协议之后，为什么很多人依然做不出一个完整的 Web3 项目？
因为学习单个知识点，与完成一个真实项目，中间还隔着很长的距离。

你不仅要会写智能合约，还要理解业务需求、设计代币经济模型、拆分合约模块、开发链下服务，并完成数据库、任务队列、链上事件监听、测试网部署和系统联调。

这些能力，才是 Web3 企业真正需要的项目开发能力。

The Web3 社区 DeFi 阶段设置了 10 个左右的企业级项目实战，其中 FishCake 是入门难度相对较低、业务闭环又比较完整的项目。

为了让更多开发者了解真正的 Web3 项目是如何开发出来的，我们决定公开 FishCake EventFi 项目的课程视频与配套资料，供大家免费学习。

## 一.FishCake 是什么项目？
FishCake 是一个将 NFT 会员、活动激励、代币经济模型、质押收益和 Web3 钱包结合在一起的 EventFi 项目。
简单来说，它尝试解决这样一个问题：线下活动、社区活动和商家活动，如何通过链上身份、活动奖励和会员体系形成持续运营的闭环？

在 FishCake 中，用户可以创建活动、参加活动、领取奖励；个人和商家可以 Mint 不同类型的身份 NFT；参与度较高的用户还可以获得 Booster NFT，并在质押时获得额外的收益权重。

它不是一个只有单个合约的练习 Demo，而是一个包含前端、App、智能合约、Go 后端、数据库、任务进程和链上基础设施的完整 Web3 项目。

## 二.项目中有哪些核心角色
FishCake 主要包含以下几类角色：

### 1. 普通用户
没有持有身份 NFT 的用户，同样可以创建和参与活动，但不能获得特定的活动代币奖励。

### 2. 个人会员
个人用户可以 Mint 个人身份 NFT，获得会员身份以及活动奖励资格。

### 3. 商家会员
商家可以 Mint 商家身份 NFT，通过平台发起线下活动、品牌活动或社区活动，并利用链上激励吸引用户参与。

### 4. 活动发起人
普通用户、个人会员和商家会员都可以成为活动发起人，在链上创建活动并配置活动规则。

### 5. NFT 持有人
持有有效身份 NFT 的用户，具备领取活动奖励和获得 Booster NFT 的资格。
通过这些角色，项目把“身份—活动—参与—奖励—质押”连接成了一套完整业务流程。

## 三.这个项目包含哪些核心功能？

### 1.NFT 会员体系
FishCake 使用 NFT 作为用户和商家的链上身份凭证。用户连接钱包后，可以选择 Mint 个人身份 NFT或商家身份 NFT。合约会记录用户身份、NFT 类型、等级以及有效期。这里不仅涉及 ERC721，还需要处理：
- 不同会员类型的价格设计
- 支付代币授权与扣款
- NFT 元数据管理
- NFT 有效期
- 用户身份判断
- 销售收入的资金分配
- Mint 完成后的奖励发放
- 管理员权限和资金提取权限
这已经不再是简单调用一次 _mint()，而是一套完整的会员业务逻辑。

### 2.EventFi 活动系统
用户或商家可以通过 FishcakeEventManager 创建活动，并将以下信息记录到链上：
- 活动名称与介绍
- 活动地点
- 开始时间与结束时间
- 活动参与规则
- 空投代币类型
- 空投数量
- 奖励发放规则
- 活动结算状态
其他用户可以查看活动、参与活动并领取相应奖励。
活动结束后，系统还要完成身份验证、活动结算、奖励发放和状态更新。
在课程中，我们会重点讲解：
- activityAdd：如何创建活动
- drop：如何完成活动空投
- activityFinish：如何结束并结算活动
- 如何避免用户重复领取
- 如何检查用户是否持有有效身份 NFT
- 如何保证活动状态流转正确
- 如何将链上事件同步到链下数据库

### 3. Booster NFT 激励系统
FishCake 中还设计了一套 Booster NFT。它并不是普通头像 NFT，而是一种具有实际业务用途的功能型 NFT。系统可以根据用户参与活动的次数、贡献度或排行榜表现，发放不同等级的 Booster NFT，例如：
- Legendary Tuna
- Epic Salmon
- Rare Shrimp
- Uncommon Fishcake
不同等级的 Booster NFT，对应不同的质押收益加成。例如，某个质押计划的基础 APR 为 9%，用户使用一个额外增加15%年化权重的 Booster NFT，那么这笔质押的收益会按照新的综合权重进行计算。在这个模块中，需要重点解决：
- Booster NFT 如何发放
- 等级和收益权重如何对应
- 一张 Booster NFT 如何绑定一笔质押
- 使用后的 NFT 如何标记
- 如何防止同一张 NFT 被重复使用
- 如何控制奖励通胀
- 如何保证奖励计算精度
  
### 4. Staking 质押系统
用户可以把 FCC 存入 StakingManager，按照质押周期和收益规则获得奖励。
如果用户持有符合条件的 Booster NFT，还可以得到额外收益加成。
课程会结合实际代码讲解：
- depositIntoStaking 的存款逻辑
- 质押记录的数据结构
- 基础 APR 的计算方式
- Booster NFT 的收益加成
- 质押周期和时间计算
- 提前退出与正常到期
- withdrawFromStakingWithAprIncome 的提现逻辑
- 本金和收益如何分别结算
- 如何避免重复提现与奖励超发
  
### 5. 代币销售与资金池
FishCake 设计了面向普通用户和特定参与者的不同销售池。
不同购买数量可以对应不同价格区间，系统根据用户支付金额或购买数量计算最终获得的 FCC 数量。
这个模块需要处理：
- 阶梯价格
- 支付代币授权
- 代币发放
- 销售额度
- 资金分配
- 暂停与恢复
- 管理员权限
- 精度与边界值
- 超额购买和库存不足
通过这一部分，可以学习到真实代币销售合约的设计方式，而不是只完成一个基础 ERC20 Token。

### 6. RedemptionPool 赎回池
项目还设计了一个 RedemptionPool，用于承接部分 NFT 销售收入和代币销售收入。用户提交 FCC 后，可以按照赎回池余额与代币总供应量计算可兑换的稳定币数量。

核心计算逻辑可以抽象为：用户可获得的稳定币数量 = 赎回池稳定币余额 × 用户提交的 FCC 数量 ÷ FCC 总供应量
这个模块看起来不复杂，但涉及很多必须认真处理的问题：
- 用户余额与授权检查
- 兑换比例计算
- 代币销毁或回收
- 资金池余额变化
- 赎回池锁定期
- 重入攻击防护
- 整数除法与精度损失
- 权限与紧急暂停
- 经济模型是否能够长期成立
课程不会只带大家看公式，还会分析其中可能存在的经济模型风险和工程改进空间。

## 四.你会学到怎样的合约架构
FishCake 的智能合约并不是把所有功能写进一个大合约，而是按照业务职责拆分为多个模块：
- FishCakeCoin：代币发行与分配
- NftManager：身份 NFT 与 Booster NFT
- FishcakeEventManager：活动创建、空投和结算
- StakingManager：质押与收益计算
- DirectSalePool：普通用户销售池
- InvestorSalePool：特定销售池
- RedemptionPool：赎回与储备资金管理
在架构设计中，我们还会重点分析：
- Interface、Storage 与 Logic 的分离
- Storage Slot 的处理方式
- 常量和 immutable 的使用
- UUPS 可升级合约模式
- 哪些合约应该升级
- 哪些合约不应该升级
- 日常运营权限、资金权限和升级权限如何分离
- 时间锁与代币锁如何设计
- 常见智能合约攻击如何防范
这些内容，才是企业级合约开发与普通 Demo 开发之间真正的差距。

## 五.项目不只有 Solidity，还有完整的 Go 链下服务
真实的 Web3 项目不可能只有智能合约。智能合约负责链上的资产与规则，链下服务则需要负责数据同步、业务查询、交易队列、异常恢复和 API 服务。

### 1. FishCake 的 Go 服务
- 区块数据同步
- 合约事件监听
- 链上事件解析
- 数据库存储
- 区块回滚处理
- 活动空投任务
- 系统空投任务
- 交易提交队列
- API 服务
- Metrics 监控指标
- PostgreSQL 数据管理

### 2. Worker 模块承担了多类后台任务
#### 2.1 clean_data_worker
负责清理和维护区块数据。课程中还会进一步讨论：只保留一定数量的最新区块记录是否合理，以及真实生产环境下应该如何进行历史数据分表和持久化。

#### 2.2 drop_worker 与 system_drop_worker
负责处理符合条件用户的空投任务。这里需要考虑任务幂等、失败重试、交易状态确认和重复发放等问题。

#### 2.3 submit_tx_worker
前端完成离线签名后，将交易提交到后端队列，再由 Worker 发送到链上。这一部分涉及：
- 交易队列
- 链上广播
- 交易回执
- 失败重试
- 状态机
- 幂等处理
- RPC 异常切换
这些都是 Web3 后端岗位面试和实际工作中经常遇到的问题。

The Web3 社区 DeFi 阶段共有 10 个左右的项目实战。FishCake 是其中业务门槛相对较低的一个，所以我们选择把它作为公开项目，帮助大家了解我们的项目实战到底在讲什么。
但“相对简单”不代表它只是一个简单 Demo。它依然覆盖了一个完整 Web3 项目所需要的主要能力：
- Solidity 智能合约开发
- ERC20 与 ERC721
- EventFi 业务模型
- 代币经济模型
- NFT 会员系统
- Staking 质押系统

- UUPS 合约升级

## 十.写在最后
Web3 开发真正困难的地方，从来不是写出一个 ERC20，或者调用一次 NFT Mint。

真正困难的是：如何把业务需求转化为合约架构，如何保证链上资产安全，如何让链上和链下数据保持一致，如何处理失败交易、重复请求和区块回滚，又如何把多个合约、后端服务、数据库与前端连接成一套可以运行的系统。

FishCake 是 The Web3 社区 DeFi 阶段最基础的企业级项目，但它已经足以帮助大家建立完整的项目开发认知。
我们希望通过这次公开，让更多开发者看到：Web3 项目实战不是复制几段代码，也不是跟着视频完成一次部署，而是理解业务、读懂架构、发现问题，并最终具备独立交付项目的能力。

如果你能完整学完 FishCake，并独立完成代码部署、业务测试和架构复盘，那么你才算真正迈出了从 Solidity 初学者走向 Web3 项目开发者的第一步。
